# AI-чат

ADP включает встроенного AI-ассистента, который может анализировать debug-записи, отвечать на вопросы о вашем приложении и предлагать исправления. Он работает в двух местах: в **Панели отладки** (полнофункциональный чат и анализ) и в **Тулбаре** (быстрый всплывающий чат, встроенный в вашу страницу).

Оба используют одно и то же подключение к бэкенду — настройте один раз в панели и используйте везде.

## Подключение LLM-провайдера

Перейдите в раздел **LLM** в боковой панели панели отладки (`/debug/llm`). Карточка подключения показывает текущий статус и позволяет подключиться к одному из поддерживаемых провайдеров.

### Поддерживаемые провайдеры

| Провайдер | Метод аутентификации | Модель по умолчанию | Модели |
|-----------|----------------------|---------------------|--------|
| **OpenRouter** | OAuth (PKCE) | `anthropic/claude-sonnet-4` | Claude, GPT-4, Llama, Mistral, Gemini и 200+ других |
| **Anthropic** | API-ключ | `claude-sonnet-4-20250514` | Семейство моделей Claude |
| **OpenAI** | API-ключ | `gpt-4o` | GPT-4o, o1, модели ChatGPT |
| **ACP** | Нет (локально) | Управляется агентом | Claude Code, Gemini CLI, Codex CLI или любой ACP-совместимый агент |

### Подключение через OpenRouter (OAuth)

1. Выберите **OpenRouter** в переключателе провайдеров
2. Нажмите **Connect with OpenRouter**
3. Откроется новое окно со страницей авторизации OpenRouter
4. Подтвердите подключение
5. Окно закроется автоматически; панель покажет статус **Connected**

OpenRouter использует OAuth PKCE flow — API-ключ не нужен. Вы получаете доступ ко всем моделям, доступным в вашем аккаунте OpenRouter, включая бесплатные модели.

### Подключение по API-ключу (Anthropic / OpenAI)

1. Выберите **Anthropic** или **OpenAI** в переключателе провайдеров
2. Введите ваш API-ключ (`sk-ant-...` для Anthropic, `sk-proj-...` для OpenAI)
3. Нажмите **Connect with API Key**
4. Панель покажет статус **Connected**

API-ключи хранятся на стороне сервера в файле `.llm-settings.json` внутри каталога хранилища ADP. После первоначального подключения они никогда не отправляются на фронтенд.

### Подключение через ACP (локальный агент)

ACP (Agent Client Protocol) подключается к локальному AI-агенту, работающему на вашей машине — API-ключи и облачные сервисы не нужны. Агент запускается как подпроцесс, управляемый ADP.

1. Выберите **ACP** в переключателе провайдеров
2. Укажите **Command** (по умолчанию: `npx`) и **Arguments** (по умолчанию: `@agentclientprotocol/claude-agent-acp`)
3. Нажмите **Connect Agent**
4. ADP запустит фоновый демон и создаст подпроцесс агента для вашей вкладки браузера

**Как это работает:**

ADP запускает постоянный процесс-демон, который управляет подпроцессами агентов через Unix-сокет. Каждая вкладка браузера получает собственную изолированную сессию агента — несколько пользователей или вкладок могут подключаться одновременно, не мешая друг другу.

```
Browser Tab 1 ──► ADP API ──► Daemon ──► Agent subprocess 1
Browser Tab 2 ──► ADP API ──► Daemon ──► Agent subprocess 2
```

**Доступные ACP-адаптеры:**

| Пакет адаптера | Агент |
|----------------|-------|
| `@agentclientprotocol/claude-agent-acp` | Claude Code (по умолчанию) |
| `@anthropic-ai/gemini-agent-acp` | Gemini CLI |
| `@anthropic-ai/codex-agent-acp` | Codex CLI |

Команда должна быть доступна в системном PATH сервера, на котором работает ADP. Процесс агента наследует окружение сервера, поэтому API-ключи для агента (например, `ANTHROPIC_API_KEY`) следует задавать в окружении сервера.

**Жизненный цикл сессии:**

- Сессии привязаны к вкладкам браузера (используется `sessionStorage`)
- Неактивные сессии автоматически завершаются через 30 минут
- Максимум 10 одновременных сессий на один демон
- Отключение из панели останавливает только сессию агента вашей вкладки
- Демон автоматически перезапускается при обнаружении несовпадения версии протокола (например, после обновления ADP)

### Выбор модели

После подключения нажмите на строку подключения, чтобы развернуть настройки. Используйте выпадающий список **Model** для выбора модели. Для OpenRouter включите переключатель **Free**, чтобы отфильтровать только бесплатные модели.

### Пользовательские инструкции

Поле **Custom instructions** позволяет задать системный промпт, который добавляется в начало каждого запроса к LLM (как для чата, так и для анализа). По умолчанию:

> Reply in English. Be concise and actionable — focus on root causes and fixes, not descriptions of what the code does.

Измените его в соответствии с предпочитаемым языком или стилем анализа.

### Таймаут запроса

Кнопка отправки показывает текущий таймаут (по умолчанию 30 с). Нажмите стрелку выпадающего списка, чтобы изменить его (10–120 с). Более длинные таймауты помогают при сложном анализе на медленных моделях.

## Панель: вкладка Chat

Вкладка **Chat** по адресу `/debug/llm` предоставляет полноценный интерфейс диалога:

- Вводите сообщения и получайте ответы AI
- Многоходовой диалог с полным контекстом
- Рендеринг Markdown в ответах (блоки кода, списки, таблицы)
- История чата хранится на стороне сервера и доступна для просмотра в аккордеоне **History**
- Повтор неудачных сообщений одним нажатием
- Удаление отдельных записей истории или очистка всей истории

Чат не включает контекст debug-записей автоматически — это диалог общего назначения с настроенной LLM.

## Панель: вкладка Analyze

Вкладка **Analyze Debug Entry** позволяет отправить отладочные данные AI для анализа:

1. Выберите одну или несколько debug-записей из списка (используйте чекбоксы)
2. Отфильтруйте записи по тексту URL/команды или быстрым фильтрам (4xx, 5xx, ошибки, медленные запросы)
3. При желании введите инструкции для анализа (например, «Почему этот запрос медленный?»)
4. Нажмите **Analyze**

Данные выбранных записей (запрос, ответ, тайминги, запросы к базе данных, исключения, логи) отправляются LLM в качестве контекста. Ответ отображается inline с форматированием Markdown.

Контекст обрезается до 12 000 символов, чтобы не превышать ограничения модели.

## Тулбар: всплывающий AI-чат

Тулбар встраивает лёгкий всплывающий AI-чат, доступный с любой страницы вашего приложения.

### Открытие чата

Нажмите кнопку с **иконкой утки** в тулбаре, чтобы открыть всплывающий чат Debug Duck.

### Как это работает

Чат тулбара использует **то же подключение к бэкенду**, что настроено в панели. Отдельная настройка не требуется.

```
Toolbar (your page)          Panel (configured once)
     │                              │
     │  GET /debug/api/llm/status   │
     ├─────────────────────────────►│
     │  ◄── connected: true ────────┤
     │                              │
     │  POST /debug/api/llm/chat    │
     ├─────────────────────────────►│──► LLM Provider API
     │  ◄── AI response ───────────┤◄──
```

### Статус подключения

Точка статуса в заголовке чата отражает реальное состояние подключения:

| Цвет точки | Значение |
|------------|----------|
| Зелёный | Подключено — AI-чат активен |
| Красный | Не подключено — сначала настройте в панели |
| Серый | Загрузка статуса... |

Если подключение отсутствует, появляется предупреждающий баннер со ссылкой на настройки LLM в панели.

### Контекстно-зависимые диалоги

Тулбар автоматически включает контекст текущей debug-записи в первое сообщение:

- Метод запроса, путь и код статуса
- Время ответа и использование памяти
- Количество запросов к базе данных и самые медленные запросы
- Исключения (класс и сообщение)
- Количество логов и deprecation-предупреждений

Это означает, что вы можете задавать вопросы вроде «Почему это медленно?» или «Объясни эту ошибку», и у AI уже будут нужные отладочные данные.

### Возможности

- **Многоходовой диалог** — уточняющие вопросы сохраняют контекст
- **Чипы-подсказки** — быстрые действия, такие как «Analyze request», «Performance tips», «Explain errors», «Suggest fixes»
- **История чата** — диалоги сохраняются в общую историю (видна и в панели)
- **Перетаскивание и изменение размера** — перемещайте окно в любое место, меняйте размер за правый нижний угол
- **Автосброс при смене записи** — выбор новой debug-записи сбрасывает диалог и формирует новую сводку

## Хранение настроек

Все настройки LLM хранятся в одном JSON-файле:

```
{storage_path}/.llm-settings.json
```

Содержимое:

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `apiKey` | string \| null | `null` | API-ключ провайдера или OAuth-токен |
| `provider` | string | `"openrouter"` | Активный провайдер: `openrouter`, `anthropic`, `openai` или `acp` |
| `model` | string \| null | `null` | ID выбранной модели (при null используется модель провайдера по умолчанию) |
| `timeout` | number | `30` | Таймаут запроса в секундах (5–300) |
| `customPrompt` | string | *(см. выше)* | Системный промпт, добавляемый в начало всех запросов |
| `acpCommand` | string | `""` | Команда ACP-агента (например, `npx`) |
| `acpArgs` | string[] | `[]` | Аргументы команды ACP |
| `acpEnv` | object | `{}` | Переменные окружения для процесса агента |

История чата хранится отдельно в `.llm-history.json` (максимум 100 записей, FIFO).

## Архитектура

```
┌─────────────┐    ┌─────────────┐
│ Debug Panel │    │   Toolbar   │
│  (Chat tab) │    │ (AI popup)  │
└──────┬──────┘    └──────┬──────┘
       │                  │
       │  RTK Query API   │  RTK Query API
       │  + X-Acp-Session │  + X-Acp-Session
       │                  │
       ▼                  ▼
┌─────────────────────────────────┐
│     /debug/api/llm/*            │
│     LlmController (PHP)        │
├─────────────────────────────────┤
│     LlmProviderService          │
│     ├─ OpenRouter (OAuth/key)   │
│     ├─ Anthropic (API key)      │
│     ├─ OpenAI (API key)         │
│     └─ ACP (local agent) ───────┼──► AcpDaemonManager
├─────────────────────────────────┤     ├─ Unix socket IPC
│     FileLlmSettings             │     └─ acp-daemon-runner.php
│     FileLlmHistoryStorage       │         ├─ Session 1 → Agent 1
│     (.llm-settings.json)        │         ├─ Session 2 → Agent 2
│     (.llm-history.json)         │         └─ Session N → Agent N
└─────────────────────────────────┘
```

Фронтендный LLM API (`llmApi`) находится в общем SDK-пакете (`@app-dev-panel/sdk/API/Llm/Llm`), поэтому и панель, и тулбар импортируют его из одного источника. Оба Redux-хранилища включают LLM-редьюсеры и middleware, разделяя одинаковое поведение кэша RTK Query.

Для ACP каждая вкладка браузера генерирует UUID, сохраняемый в `sessionStorage`, и отправляет его в заголовке `X-Acp-Session` с каждым запросом к LLM API. Демон сопоставляет ID сессий с подпроцессами агентов, обеспечивая изоляцию на уровне вкладок.
